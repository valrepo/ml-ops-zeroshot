# Tasks: Zero-Shot Text Classification Platform

**Input**: Design documents from `/specs/001-zero-shot-platform/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: REQUIRED (Constitution Principle VII).
- Unit tests run with no network access and no model downloads; they use the fakes in
  `tests/fakes.py`.
- MinIO behavior is covered by integration tests against a real MinIO. They are skipped
  locally when MinIO is unreachable, and they **fail** when `REQUIRE_MINIO=1` is set.
- Within each story, write the tests first and confirm they fail before implementing.

**Organization**: one phase per user story, in priority order. Story labels match the spec:
`[US1]` is US-01, `[US7]` is US-07, and so on.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on unfinished tasks)
- **[Story]**: which user story the task belongs to
- All paths are relative to the repository root

## Conventions every task MUST follow

- Design decisions are already made. Implement them as written in the referenced documents:
  research R1–R13, the data model sections, and the contract files. Do not re-decide them.
- Core modules (`src/zeroshot/**` except `ui/`) MUST NOT import `streamlit`. `ui/` MUST NOT
  import `transformers`, `huggingface_hub` or `minio`. `services/classifier.py` MUST NOT
  import `services/model_manager.py` or `services/storage.py` ([contracts/services.md](contracts/services.md)).
- Raise only the `ZeroShotError` subclasses from `src/zeroshot/errors.py`, using the `code`
  values listed in [contracts/services.md](contracts/services.md).
- Log with `zeroshot.logging.log_event(...)`, using only the event names in
  [contracts/services.md](contracts/services.md). Never log `input_text`, tokens or
  credentials.
- Use Python 3.14 syntax, full type hints, and code that passes `ruff check` and
  `ruff format`.

## Phase 10: User Story 4 - Delete a downloaded model (Priority: P3)

**Goal**: safe, confirmed deletion of a managed model; refused while the model is in use
(US-04, AC-08).

**Independent Test**: with one ready model and no lease, `delete` removes only
`MODEL_DIR/<slug>/<rev>/`, and the model becomes `NOT_AVAILABLE`. While a lease is held,
`delete` raises `ModelInUseError` and nothing is removed.

### Tests for User Story 4 (REQUIRED per Constitution VII) ⚠️

- [X] T070 [P] [US4] Write `tests/unit/test_model_manager_delete.py` covering:
  - deletion removes the install directory, and the parent `<slug>/` directory when it is
    empty;
  - `HF_HOME` content and the other model are untouched;
  - the status becomes `NOT_AVAILABLE`;
  - with a lease held, `ModelInUseError` is raised, the directory still exists, and
    `model.delete.refused` is logged;
  - a new lease attempted while `exclusive()` is held during deletion is refused;
  - a catalogue entry whose resolved path escapes `MODEL_DIR` (a symlinked `<slug>` pointing
    outside) raises `PathSafetyError`, and nothing outside is removed;
  - `shutil.rmtree` raising `OSError` produces `ModelDeleteError` and the state is
    refreshed;
  - `registry.notify_removed` is called, so a registered callback receives the key;
  - deleting a model that is not ready raises `ModelNotReadyError`.

  parent. Afterwards it calls `registry.notify_removed(model_key)`, clears `_state`, and logs
  `model.deleted` (or `model.delete.refused`).
